# Changelog

## [Unreleased]

- Added workspace Hosts enrollment and connection status, explicit environment machine assignment/replacement/unassignment, editable ports/health/ingress, and optional setup host selection. Assignment failures retain the created project and direct retries to Hosting.

### Added

- Self-hosted frontend image. `Dockerfile` takes fixed build arguments (`NEXT_PUBLIC_API_BASE_URL=/api/v1`, `ALPHACI_BUILD_PROFILE=enterprise`, `ALPHACI_EDITION=enterprise`) so one image serves every customer behind a same-origin proxy, and pins the dev-only mock and quick-login switches off. The image gets a `HEALTHCHECK` against a new `GET /healthz` liveness route that does not call the backend. Unset arguments keep the hosted build unchanged. See `docs/runbooks/runbook-selfhost.md`.
- A backend repository's Overview shows one environment at a time: **Production** and **UAT** are tabs (each with its branch and state) over a single deployment card, instead of two stacked cards, so only the selected environment's log tail runs. Arrow keys, Home and End move between the tabs. A project without a backend uat keeps its Production card as before. The Overview card's log tail no longer draws the browser's light scrollbar; it still scrolls.
- A backend repository's Overview shows each environment as a card: UAT now gets one like Production, with live logs, its deploy facts (how long it took, what started it) and a folded **Recent deploys** list (status, commit and message, trigger, duration, when). A frontend repository's uat stays a row. A live log tail that has been silent for 15 minutes says the service may be asleep (a free instance stops without traffic and starts on the next request) instead of looking frozen.
- Hosting: a service that tracks one branch opens on that branch's environment and no longer shows an empty "Production · not deployed" tab when main has its own service. An image-pushed service's header says "deploys the pipeline's image" without a build command, and each deploy row shows its trigger and duration, "Replaced" for a deploy a newer one replaced (Render's `deactivated`, the new `superseded` status), and the commit message the previews looked up. Needs the matching backend change for commits, messages and the new status.
- The Code tab shows what last changed each file and folder, as GitHub does. Above the list, a bar names the latest commit of the open folder (or file): author avatar and login, the first line of its message, short sha, how long ago, and the commit count ("288 Commits", the branch's total at the root). Each row shows its last commit's message (truncated) and time ("3d ago", exact date on hover), with folder and file icons. The file list renders first and the column fills in from `GET workspace/files/commits` when it arrives. A failure leaves the list exactly as before, with no error. File sizes moved off the rows and stay in the file view. Nothing links to GitHub.
- A Project in the explorer (`/workflows`) has a **Members** action for Product owners and admins. It opens the Project page on its members panel (`#members`), where Developers are added and get GitHub Write. Before, the panel was reachable only from a System page, Home items, notifications or breadcrumbs. The panel scrolls itself into view once loaded, because it renders after the page's own data.
- Iterations phase 3, **Start the next iteration** (ITERATIONS_PLAN.md §6, decisions D2 and D5, problem P15). Once a Project's iteration is delivered, a Product owner or admin the server lets start (`canStartNext`) gets **Start iteration N+1** in PO Studio's delivered banner, beside the Project page's iteration pill, and in place of the waiting sentence on the QA run and My QA items. It opens a dialog: an optional **Goal** (at most 120 characters) and a **Carry over** list of the delivered iteration's items grouped by requirement (kind chip and name), each with a checkbox and its Progress and QA status ("Done · QA: Returned to dev · restarts In progress"); the unfinished items (`suggested`) start ticked, with **Select all unfinished** and **Clear**. Starting calls `POST /delivery-projects/:id/iterations` (`iterationsRepository.start`) and then re-reads the Project's iteration, requirements, QA run and My QA items (one per-Project signal every one of their ViewModels watches) and PO Studio's promotion status. `ITERATION_ACTIVE` ("Iteration N is still active. Deliver it before starting the next one.") and `ITERATION_CARRY_INVALID` read as product sentences and keep the dialog open. Everyone else reads "Iteration N was delivered on <date>. Waiting for the Product owner to start iteration N+1." in QA Studio and the Project's QA run tab (no Start a run button), in the Project's My QA items and the repository Overview's My QA items summary (instead of the buckets and counts), and under the Project in a Developer's Home **My work**. Where an iteration is named, its goal follows: "Iteration 4 · Loyalty points · Active". On the Project's screens, a backend that does not send `canStartNext` (or sends it without `carryOver`) shows none of this; Home's line follows the team overview's per-Project `iteration` alone.

- Iterations phase 2, **Delivered** (ITERATIONS_PLAN.md §6). A Project's header (the repository page's Overview identity, for a Project of any size, and the Project page beside its status) shows **Iteration N · Active** or **Iteration N · Delivered 14 Oct** (the viewer's locale), read from `GET /delivery-projects/:id/iterations/current` through a new `iterationsRepository` and the leaf slice `@/features/checklists/iteration`. PO Studio reads each covered repository's stored delivery state (so a reload still shows what is in main) and the promotion status's `repositoryDelivered` / `iterationDelivered` (replacing the in-memory "already merged" flag when the server sends them). For a Project with more than one covered repository and `canMergeAll`, a Product owner or admin gets **Merge all repositories** (`POST /delivery-projects/:id/promotion/merge-all`): confirmed first, then each repository's result (merged, already in main, or not merged with the server's words), and **Retry the rest** after a partial failure. Once the iteration is delivered, Merge to main gives way to a banner, "Iteration N delivered on <date> by @login", listing how each repository reached main; the readiness chip turns violet and reads "Iteration N delivered". A merge answered "main already contains this commit" reads as a success, not as GitHub refusing. A delivered iteration's QA run and Project requirements say "Iteration N was delivered. Changes are locked." and withhold every control (Verification, sign-off, reopen, Run Playwright, evidence, requirement edits and Progress). `ITERATION_DELIVERED`, `QA_PROMOTION_BLOCKED` and `PROJECT_HAS_NO_REPOSITORIES` read as product sentences wherever a write can surface them. Every new field and route is optional: with an older backend (a 404, or the fields absent) every screen is exactly as before.

- Added the on-prem choice to project setup. Where the deployment offers on-prem hosts (`GET /deployment-providers` lists `onprem-compose` enabled), each environment in the Environments step gets **Runs on: Managed hosting | On-prem host**, with a "Run every environment on-prem" quick action. Every environment on-prem sends one on-prem target per environment and deployable slot and no Render or Vercel target, and the Delivery step drops the hosted target pickers, Render options and the Render-variable rule for a note to register the host on the project's Hosting tab. A mix keeps the hosted targets for the managed environments and adds each on-prem environment's own targets, so no environment mixes the two. Review shows where each environment runs. Listed but off shows the option disabled with the server's reason; not listed, or a failed read, leaves the wizard and its request exactly as before.

- Added an opt-in Environments section to single-repository project setup. It starts from the editable Test (`dev`), UAT (`uat`), Production (`main`) template; environments can be renamed, reordered, added, removed, share a branch, and exactly one is production. The branches to be created are previewed, and lists the backend would refuse are caught before the request. Setups that leave it off keep the fixed `dev, uat, main` path.

- Added the Environments section at the top of a project's Hosting tab. Each project environment is listed in promotion order with its targets per slot, the release it runs (commit and image digests), anything in flight, and its recent deployments. Later environments offer one Promote action for the release the previous environment runs, show the backend's reason when a promotion is refused, and ask for a second click before deploying to production. When on-prem hosts are enabled, on-prem environments can register a host and show its token once. Projects on the legacy branch path are unchanged. On-prem targets are labelled "On-prem host" instead of falling back to Render.
- QA evidence screenshots on Project run items (QA_ATTACHMENTS_PLAN.md, A1). Each item in QA Studio and the Project's QA workspace gains an **Evidence** section: thumbnails with a count, a caption, the uploader and time, and a click-to-enlarge lightbox (modal dialog on `<body>`: focus on Close, Tab stays inside, Escape closes, arrow keys step between images, alt text from the caption or "Screenshot n of <item>"). Where the run is open and the server allows it (`attachments.canAdd`), **Capture** (QA Studio only: `getDisplayMedia` with `preferCurrentTab`, one frame, sharing stopped at once, cropped to the preview iframe by Region Capture where the browser has it, else by its on-screen box), **Paste** (Ctrl/Cmd+V into the focused Evidence area) and **Upload** (PNG, JPEG or WebP, checked by its bytes) add a screenshot, compressed in the browser first (WebP, else JPEG; longest side 2560px; aiming for 500 KB, refused over 3 MB), with an optional caption. Delete asks inline and is offered only where the attachment says `canDelete`. A signed-off run shows its evidence read-only. The whole run's list is read once (`GET /delivery-projects/:dp/qa-runs/:runId/attachments`) and again when a five-minute signed URL runs out; uploads are multipart through `qaAttachmentsRepository` (`request` no longer forces a JSON Content-Type on a `FormData` body). The evidence error codes (`QA_RUN_SIGNED_OFF`, `QA_ATTACHMENT_LIMIT`, `QA_ATTACHMENT_TOO_LARGE`, `QA_ATTACHMENT_TYPE`, `QA_ATTACHMENT_FORBIDDEN`, `QA_ATTACHMENTS_UNAVAILABLE`) read as product sentences. A backend that sends no `attachments` answer, or says storage is off, hides all of it and nothing else changes.
- The printable Project QA report shows each item's screenshots on a row under the item (the report's frozen `items[].attachments` ids, with signed URLs from one read of the run's list), and waits for them to load before it opens the print dialog. The "Visual evidence" appendix is unchanged.

- Home is laid out per role (`homeLayoutFor`, an allow-list per role), each with five metrics, two main blocks, two side blocks and its own keyboard shortcuts, still one screen at 1024x720 and up. A Developer (`member`) sees **Returned by QA** per Project (opening its My QA items), their pipeline runs failures first, **My work** (their Projects' repositories with the latest run, and Add repository) and Quality. The QA Team sees **Projects in verification** (a verification bar per Project, opening QA Studio on its frontend), **UAT automation** (the latest uat run and verify stage per repository), **Ready for re-test** and **Defects by severity**. A Product owner (`lead`) and an Admin see **Ready for production** (signed off Approved or Conditional, not merged to main everywhere, opening PO Studio), **Branch health** (dev / uat / main per repository, with failure streaks), **Projects needing attention** (no Features, or no Developers, with Create project) and Quality. N is Add repository for a Developer and Create project for a Product owner; the QA Team has no N.
- "My Projects" are the Projects the viewer is a member of in their role (`viewerMembership`); with none, the blocks cover the team's Projects and say so. A role's Home reads only what it shows: never the team walk or Activity. With `qaChecklistsEnabled` off, Developers and Product owners get run-based blocks and the QA Team gets the team dashboard; a session with no known role keeps the team dashboard. An empty team shows the get-started journey to Product owners and admins, and "Waiting for your Product owner to create the first Project." to Developers and the QA Team.
- `requirementsRepository.teamOverview(workspaceId)` reads `GET /workspaces/:id/qa-requirements/overview` whole. The newer per-Project `latestRun`, `counts`, `promotion` and `viewerMembership` read as not known from a backend that does not send them, and the blocks that need them say so.
- Added the Teams project explorer: the team rail's Repositories entry becomes **Projects (n)**, listing each team Project (hierarchy delivery project) with its repositories as role chips (Frontend / Backend / Service / App) that open their dashboards, a checklist count, and an Unfiled group. Opening a Project shows its repositories, "Verify in QA Studio" (the frontend repository, else an app; QA Team, Team lead and Admin), "Create repository in this Project", per-repository "Move to another Project" (409 "moved by someone else" refetches; an emptied Project can be archived), and attach/detach of checklist templates through `PATCH /qa-checklists/:id/projects` so shares outside the Project are never touched. Leads get "New Project". The Workflows studio's Current Projects pane shows the same explorer. The team QA checklists section is relabelled **Checklist templates**.
- The Create Project wizard now honours `?group=` (preselects the team) and `?project=` (sends `deliveryProjectId` and shows "Project: team / project"); malformed or foreign ids are ignored.

- Added QA Studio: a project tab in the Delivery group that frames a deployed branch (Desktop / Tablet 768 / Mobile 375, same-host route field, reload, open in new tab) beside a verification run of a shared checklist against the commit the server resolves. Testers record each item's status, notes, severity and reproduction steps (severity required for Failed and Returned to dev), sign runs off as Approved / Conditional / Rejected with the eligibility reasons shown, and leads can reopen a signed-off run. Every right comes from the server (`item.canUpdate`, run `permissions`); stale writes (409) offer "Reload run". The project Overview gains a "Returned by QA" card where Developers, Team leads and Admins mark an item fixed and request a re-test. Both are gated by `qaChecklistsEnabled`.

### Changed

- Home's **Ready for production** now matches the merge gate: only an **Approved** sign-off counts (Conditional no longer does), a Project whose iteration the overview reports as delivered is left out, and the merged count is the server's stored `mergedRepositories`.
- Cleaned up the Create project wizard. **Delivery** has one project-wide **Hosting** choice (a segmented radio group): **Vercel / Render** (default), **On-prem host** and **None — CI only**. It replaces both the "Provision deployment target" switch and the per-environment "Runs on" control. Vercel / Render sends today's hosted targets and no `environments`; On-prem sends the fixed `dev`, `uat`, `main` environments with one `onprem-compose` target per environment and slot, and nothing hosted; None sends `deploymentProvisioning: { enabled: false, targets: [] }`. On-prem is offered only where `GET /deployment-providers` lists it (disabled with the server's reason when off) and is disabled for two-repository projects. The environments are shown read-only (dev → uat → main); the environment editor is gone, while its rules stay in the model. The Render-variable rule applies to Vercel / Render only.
- The Vercel / Render cards show only what takes effect: the service or project name (named after the repository until edited), Render region and instance, and the target's variables with where they apply. Build and start commands, runtime, root directory, deploy method and ownership are no longer shown (their defaults are still sent). Shared defaults are collapsed by default.
- **Repository** no longer asks for a service name or path: the service is always the repository's slug at `.`. **Automation** keeps Node version (Node stacks) and Coverage; the workflow check chips and the workflow file name are gone, and every create sends all workflow options on with `docker: true`, so managed Render and on-prem deploys get their `./Dockerfile`. **Review** shows Hosting and Environments.
- A known Project (a resolved `?project=` link, or a Developer's pick) now fixes the team: the team box is replaced by the Project line and `workspaceId` is that Project's team. A Developer with several teams can let a picked Project go ("Change team"). The steps share one field grid that collapses to one column on narrow screens.

- Home's run cards open the run's repository on its **Pipeline** tab in ALPHACI (`/projects/:id#pipeline`, the Project found by repository name in the Projects list) instead of always `/runs`, which stays the fallback for a repository the list does not know. A failed run shows one line under its stages saying why, in the failing stage's own words ("Verify: 2 browser tests failed"), when the run carries a message for it.
- `/runs` shows the same per-test list and SonarCloud panel as the repository Pipeline tab (`TestCaseList`, `SonarPanel` from `@/features/runs/test-report`) under an expanded stage that reported them.
- QA Studio's Playwright stage cards: a failed stage with no test counts shows its first error message instead of "No test counts reported", and an unreported Verify stage says "Not run: Quality failed on a1b2c3d first (...)" when Quality failed on the same commit. Both read optional `friendlyMessages` / `reason` on the stage and fall back to the old lines when a backend sends neither.
- The repository page's **Hosting** and **Environment** tabs are one **Hosting** tab, organised by service: a service header (provider, name, status, build settings in one line, Logs and Sync, and a "⋯" menu with Edit build settings, Reinstall deployment secrets, Open in Vercel/Render and Detach, each opening inline), an environment switcher (Production `main`, UAT `uat`, Previews (n), WAI-ARIA tabs with arrow keys), then the selected environment's **Deployment** card (status, address with Copy and Open site, the last five deploys with All deploys, the preview branches with their pull requests, custom domains on Production) beside its **Variables** card (that lane's keys and who set them, Add and Bulk edit scoped to it, and for preview lanes a check listing the keys Production has that the lane lacks, with a button that prefills them). A provider that does not answer gets one amber notice with Retry instead of the error twice. Branch previews stay on the Overview only. The Variables card is for Developers and admins (`canManageEnvVars`); other roles see Hosting read-only, as before. With no service, the tab is one "Host this repository" card around the existing create/register flow. `#environment` links open Hosting on Production with Variables focused; `#hosting` and the Overview's Full logs work as before.
- The repository page's **Pipeline runs** and **Workflow** tabs are one **Pipeline** tab (a Developer's strip goes from ten tabs to nine). It opens on **Runs**, which reads as the Pipeline runs tab did under one slim row: the view's name at the left and a compact **Runs | Configuration** toggle at the right (two WAI-ARIA tabs, one tab stop, arrow keys, Home and End). **Configuration** is the Workflow tab's content, unchanged. Every role that had Pipeline runs gets Pipeline; the toggle shows only where Workflow showed before (`pipelineConfigurationAvailable`), and without it there is no toggle. `#runs` and `#pipeline` open Runs, `#workflow` opens Configuration; choosing a tab by hand returns to Runs. Runs' and the studios' "Update the workflow" open Configuration, "Review in Pipeline runs" is now "Review in Pipeline", and the new-project links go to `#pipeline`.
- The `lead` role is labelled **Product owner** wherever a role is named (sidebar badge, team switcher, team roster, admin user list, and the permission and empty-state sentences that named a Team lead); the roster labels `admin` **Admin**, and the admin user list labels `member` **Developer**. The Home greeting carries the role badge.
- Repository tabs follow the viewer's role (an allow-list per role): a Product owner (`lead`) gets only Overview, Checklists, QA Studio, Audit and Settings; a Developer gets Environment as well as Hosting; QA Team and Admins are unchanged. A deep link to a hidden tab lands on Overview. Hosting, custom domain, deployment-secret and environment/repository variable writes are for Developers and admins (Product owners lose them, as on the backend); the `ENV_VARS_LEAD_ONLY` / `HOSTING_LEAD_ONLY` refusals read "Developers and admins can change ...".
- The repository Overview is the same lean page for everyone: branch previews, a compact **My QA items** summary (a count per state — Returned, In progress, To do, Ready for QA — and **Open checklist**, to the Project's My QA items or this repository's Checklists tab, which now carries the full list), the Developer's production readiness card, and the failure reason. The facts grid, Manage access, local snapshot, health checks and drift findings are gone, with their Overview reads.
- The Audit tab is readable: each event in words (with the server's message as a fallback), its actor or "System", a relative time with the exact time on hover, a "Project" tag for Project-scoped events, and **Load more** over `GET /projects/:id/audit?limit=50&before=<next>`. It says when audit recording is turned off.
- The team Activity feed is hidden (`SIDEBAR_SHOWS_ACTIVITY = false`): no sidebar entry and no Home Activity rail. `/activity` and `/groups/:id/activity` still work.
- Restructured team navigation around the header's workspace picker, the only team selector. The Projects page (`/workflows`) lost its team dropdown and its team rail: it shows the header team's Project cards (no per-repository chips) under a plain "Projects" heading, with one primary **Create project** and a "⋯" menu holding **Empty project** and **Add repository** (WAI-ARIA menu button). The team's other sections are pages of their own: **Teams** (`/teams`) is the members page, and the sidebar gains **Checklists** (`/checklists`, with the QA checklists capability) and **Activity** (`/activity`); team settings moved to a lead/admin-only **Team** tab on `/settings`. The Overview section is gone. Platform admins see teams they are not a member of in the header picker under "Other teams (admin)". Old `/teams?section=…` links are forwarded, and "Manage project" / checklist manage links point at the new pages. The Settings page's workspace members list is read-only with a link to Teams; the frontend no longer calls the `/workspaces/:id/members` write routes.
- Updated the local catalog fixture to `@alphaci/capability-catalog@0.2.0`, including typed capability surface data.
- Regenerated the capability snapshot and OKF surface view from the vendored package; frontend checks now fail on surface drift.
- Changed capability and pack documentation checks to use the versioned package contract instead of a sibling backend checkout. Package publication remains outside this local change.
- Consolidated the root README and feature/shared notes so architecture and product status live in the documentation bundle.
- Made ADR-0003's rejected alternative precise, separating rejected pack duplication from permitted build-time exclusion.

### Fixed

- Opening the log of a queued or running job no longer says "ALPHACI can't read this log: its GitHub connection has no access to Actions logs". GitHub provides a job's log only once the job finishes and answers 404 until then, which the backend reports as missing access. A job row now asks for nothing while its job is unfinished and says "Log not ready yet: GitHub only provides a job's log once the job finishes, and this job is still running" (or "has not started yet"). When the job finishes, which the run's polling picks up, the open panel offers **Show log**.
- Dark theme: secondary buttons (`.ghost-button`, and the Hosting tab's buttons and "⋯" trigger) had a `#363642` edge on `#24242d` cards (about 1.3:1), so Refresh, Preview, Check again and the like read as plain text. They now use a new `--border-control` token (`#787886`, at least 3:1 on the card, page and nested tile) and `--control-text` (`#e4e4ea`) for the label; hover fill and the focus ring are unchanged. Light theme keeps its existing values.
- Home's stage dots drew `stalled` and `blocked` stages as grey pending dots on a red card. Stalled is now an amber ring that does not pulse; blocked is a muted outline with a slash.
- A GitHub run that concluded `startup_failure` (GitHub refused to start the workflow) is a failure: red on the Pipeline tab's commit headline, run and job chips, run rows and CI run list, failed in promotion readiness and in a tool check's tone. It used to be neutral grey. One rule, `isFailedConclusion`, now decides this for the project page.
- Terminal colour codes stored with Playwright output (`\u001b[2m...`) no longer show as stray `[2m` text: test records, failing-test names and messages, friendly messages on `/runs` and the Pipeline tab, Home's failure line and QA Studio's stage reasons and failure list all pass through `stripAnsi` (`@/shared/ui/strip-ansi`).
